## #121 live 回合中途恢复 → 同一段正文被塞进首行并在后续行重现 [已收口]

- 现象（主人 2026-09-15 08:58 真机截图，会话 `20a4a6c7a7f5`，回合进行中「已工作 01:50」）：`思考×1` 卡 → 正文段①（**6 行 = 3 个自然段** s1+s2+s3）→ `查看技能×1,终端×1,思考×1` 卡 → 正文段②（s2 整句）→ `读取文件×1,终端×1,思考×1` 卡 → 正文段③（s3 整句）→ `执行代码×2,终端×1,思考×1` 卡。四卡均折叠（像素高度各 108px）。
- 取证：像素+OCR 确认段①3 个自然段、段②③各 1 个，且段②③左右端 x 区间与段①第 3/4 行、第 5/6 行**逐像素相同**；`state.db` 服务端三行各独立无重复（180659 = s1+[skill_view,terminal]，180664 = s2+[read_file,terminal]，180667 = s3+[terminal,execute_code]）→ 重复只在客户端渲染层。
- 根因（行号）：回合中途 transcript 重载时 `chat_diff_merge.dart` 规则 5（temp 流式行 + 120s 窗）把 live 行**替换**成服务端本回合首行，`_patchMessage` 前缀取更长 → 该行 content 变整轮正文，同时 `streamingAssistantMessageId` 悬空 → live 层整层消失；`transcriptMessagesProvider` 只跳过流式消息自身，本回合其余服务端行照常渲染 → 同一段正文两遍。
- 修复：
  1. `diffMergeMessages(liveStreamingMessageId:)`：活跃流式缓冲**已超出**该服务端行（严格更长且完整包含，即真机多段在手形态）→ live 行保身份 + 服务端行另行入列；缓冲**等于/落后**该行 → 沿用既有承接语义（重连 replay 游标按行对齐、收尾按 transcript 定稿依赖它）。调用点 `chat_controller.dart` 两处传入 `state.stream.streamingAssistantMessageId`。
  2. `chat_providers.dart` 新增 `_LiveCoverage`：live 层存活且已有正文时，跳过「本回合起点之后且正文已被 live 正文覆盖」的 assistant 行；未覆盖的行照常渲染（不丢内容）。
