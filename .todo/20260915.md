## [已收口] #122 更新检查提示的「新版本」永远停在最新 Release，且可能比本机还旧（主人 2026-09-15 报告）

- 现象（主人真机截图 11:18）：手机实际装的是 0.1.48+54（设置页「版本」显示的是真实值），「检查更新」却弹「发现新版本 v0.1.47」——既比本机旧，也不是刚发出去的 0.1.49。
- 根因（源码级取证，两条叠加）：
  1. **A：v0.1.48 / v0.1.49 从来没有 GitHub Release**。检查更新打 `https://api.github.com/repos/silent-reader-cn/hermes-ui/releases/latest`（`lib/core/update/update_checker_service.dart:17-18`），而这两版只推了 git tag + commit → API 眼中的「最新」仍是 v0.1.47（`gh release list` 实证：v0.1.47 为 Latest，2026-09-14T12:43:46Z）。
  2. **B：比对基准是硬编码常量且漂了 18 个版本**。`lib/core/update/version_info.dart:5` `const appVersion = '0.1.31'`（最后一次同步是 `345f08d`「bump to 0.1.31+34」，此后每次 bump 都没同步），检查服务拿它当「当前版本」→ `newer('v0.1.47', '0.1.31')` 恒为 true → **哪怕装到最新版也永远提示有更新**。且设置页展示版本走 `package_info_plus`（真实值，`settings_providers.dart:25`），与比对基准两处不一致。
- 现状 vs 预期：现状＝提示号停在最新 Release 且不可信（旧于本机也照样提示）；预期＝基准为本机真实版本，有更新才提示，装完不再重复提示。
- 修复：
  - **B（代码）**：`UpdateCheckerService` 新增 `currentVersionResolver`（默认 `platformAppVersion` 走 `package_info_plus`，与设置页同源），`checkForUpdates` 内先解析真实版本再比对；解析异常安全回退兜底常量；显式注入 `currentVersion` 仍最高优先（既有测试零改动）；`appVersion` 降级为纯兜底常量并同步至 0.1.50；`version_info_test` 改为断言 `appVersion` 与 `pubspec.yaml` 的 X.Y.Z 一致，消灭「升版忘记同步」这个陷阱。
  - **A（发布）**：建 GitHub Release `v0.1.50`（资产：`app-release.apk` + `HermesUI-0.1.50-x64-setup.exe`，`--latest`，notes 归集 `v0.1.47..HEAD`），并在 notes 里点明 v0.1.48/v0.1.49 的 tag 缺口。
