## [已收口] CI 平台门控缺失（Linux 7 例假红）

- 现象：`analyze-test` / `coverage` 在 Linux 上 7 例红，全是两轮前新增的
  `chat_actions_trailing_invariants_test.dart`（A 窄屏转场 + B 尺寸矩阵 320/375/899）。
- 真因：`Expected: at least one matching candidate / Actual: Found 0 widgets with key
  [<'chat-open-project-folder'>]` —— 生产判据是 `hasWorkspace && (isWide || (!kIsWeb && Platform.isWindows))`，
  非 Windows 窄屏**本就不渲染**该按钮，而守卫无条件断言它存在 ⇒ 平台性假红（#119 家族老坑）。
- 修法（Windows 行为逐字不变）：新增 `folderVisibleOnThisHost(tester)`（与生产判据同源）并按它门控
  `requireFolder` / 对比度遍历 / B 矩阵的 trailing 参照（改用「⋯」左缘）。提交 `2fe707d`。

## 教训（已沉淀）
1. **新增 UI 守卫必须与生产判据同源做平台门控** —— 只在本机（Windows）跑绿不算数；凡断言里出现
   `Platform.isXxx` 分支产生的 widget，都要把该分支写进断言条件。
2. **发版前必查 CI 是否真绿**：本轮 v0.1.71 tag 的 CI 一度红（上述 7 例），根因与产品无关但会让
   「发布即红」，故修完后把 tag 挪到绿提交（Release 资产不变，因为修的是测试）。
