## Hermes UI v0.1.74

从 v0.1.73 到 v0.1.74 的累计更新（App 内「检查更新」会直接跳到本版）。

本轮两件事：**界面缩放真正生效**，以及**两处宽屏 UI 缺陷收口**（弹层越界、卡片描边被盖）。

### 界面缩放：从「只改数据」到「真放大」

**问题**（主人报告）：设置里的 100/125/150/200% 档位切换后画面纹丝不动——「百分比缩放对字体和布局无效」。

**根因**：原实现只覆写 `MediaQuery` 的 `size` / `devicePixelRatio`。渲染用的逻辑像素坐标系由引擎真实
dpr 决定，**只改 MediaQuery 数据不改变任何绘制尺寸**（字体、间距、图标全不变）⇒ 数据改了、屏幕没变。

**改法**：两段式，缺一不可——
- `MediaQuery` 覆写（`size / factor`、`devicePixelRatio * factor`）：内层按缩小视口布局，各页宽窄屏判定随之生效；
- 新增**绘制缩放层** `Transform.scale(factor)` + `OverflowBox`：把布局好的画面按系数放大画回真实视口
  —— 「看得见」的缩放靠这一步。`OverflowBox` 保证内层仍拿到缩小视口，且 `Transform` 自身尺寸等于真实
  视口 ⇒ 放大后整屏仍可命中。

实测 150%：固定 100×100 盒子在屏上 = 150×150、文字 ×1.5、内层布局仍 853×533、五点命中 5/5；
100% 档原样返回，既有像素与金照零影响。

### 宽屏弹层：改按宿主 Overlay 收敛（修「模型选择弹窗右侧出屏」）

**问题**（主人报告）：宽屏下模型选择弹窗右侧出屏、被窗口右缘裁掉。

**根因**：路由挂在 go_router `ShellRoute` 的嵌套 Navigator 上，宽屏外壳把这只 Navigator（连同它的
Overlay）放进**右侧详情栏**——比视口窄一条侧栏（实机 341.9pt）且整体右移。弹层由这只 Overlay 定位，
坐标系就是详情栏；而定位壳原先用 `MediaQuery` 的**整窗宽度**算横向 clamp 上限 ⇒ 多放行一条侧栏宽
（实机视口 1638.4 vs 宿主 Overlay 1296.5）。

**改法**：定位壳的边界改取**宿主 Overlay 的盒子**（与同族 `adaptive_popover` 一直以来的口径对齐）；
聊天**大纲弹层**有同一类问题，一并修。实测弹层卡片右缘 2120.5 → 2038（窗口 2048，留 10pt 安全边距）。

### 宽屏筛选：段卡片 1px 描边恢复可见

**问题**（主人报告）：「为什么只有两个『全部』项的外框正常？其他行都没边框了」。

**根因**：`CupertinoListSection.insetGrouped` 把段卡片的 `decoration`（白底 + 1px 描边）画在**子项之下**，
而未选中行底是不透明白 `#FFFFFF`、又铺满整段宽度 ⇒ 描边被整段盖掉。整屏只剩「显示」段（该行从未传
背景色）与选中行（半透明灰底让描边透出）看得见外框。

**改法**：宽屏的行底交还给它所在的段（未选中不画底）；暗色下选中行底与段面同色、画了只是白盖描边、
像素无差，同样不画 —— 描边这才连续（否则每段顶边与圆角会缺一段）。**窄屏维持既有行底，逐像素不变**。
